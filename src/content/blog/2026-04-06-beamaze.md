This was the first thing I ever tried to build with Claude.

I didn't really have a problem to solve. I had a question: what does it actually take to stand up an application with AI? What does the design need to be? What does the prompt need to say? What do you have to figure out about the UI before anything works?

It felt like getting a new box of markers. You know they make marks. You don't know what colors are in there, what styles they're good at, or when to reach for which one. The only way to find out is to start drawing.

So I picked something I'd actually use: a way to start any skill.

## What it does

BeAmaze lets you pick a skill (bass guitar, watercolour, Python, whatever) and turns it into a plan you can follow. AI builds the lessons. Each lesson comes with an explanation, a YouTube video to watch alongside it, and a short quiz so you know you're on the right track. You can add your own lessons too. A dashboard tracks what you've finished, your streak, and your quiz scores.

The later version adds onboarding that asks how often you want to practice, how long your sessions are, and what your goal is, then builds a four-week schedule around that.

## The stack

- **Claude chat** for the first version, built as an interactive widget in a single conversation
- **React 19 + TypeScript + Vite** for the real version
- **Tailwind** and **Framer Motion** for the UI
- **Zustand** for state, saved locally (no account needed)
- **Anthropic SDK** for lesson plans, lesson content and quizzes

## What I actually learned

**The interface lies first.**

The first version looked done in about ten minutes. Sidebar, progress bars, lesson cards, a quiz with green and red answers. Then I clicked "AI generate plan" and got "Failed to generate — try again." Every time. It took a debug panel to find out the widget couldn't reach the API at all, and couldn't save anything either. A polished screen told me nothing about whether the thing worked.

**Ask for what the AI can actually know.**

My first prompt asked the AI to pick a YouTube video ID for each lesson. It can't know that. It guesses, and a guessed ID is just a broken embed (or worse, a Rick Roll). The real version asks for YouTube *search terms* instead. Same idea, but now the AI is doing something it's actually good at.

**Where it runs is part of the design.**

I thought the hard part would be the prompts. It was the plumbing. The chat sandbox blocked the network, so the "app" ended with Claude writing a watercolour lesson plan in chat for me to paste in by hand. Moving it into a real project with my own API key fixed that in an afternoon. Knowing which box a tool works inside is one of the colors you have to learn.

**The first experiment is for learning the crayons.**

None of this was wasted. Every experiment after this one went faster because I'd already found out what the tools could and couldn't do. That was the point.

## What's next

BeAmaze runs locally and does what it's supposed to. It isn't deployed, and the API key lives in the browser, which is fine for me and not fine for anyone else. A small backend would fix that. Maybe someday. For now it did its job: it taught me what's in the box.
